# Fangorn audit — 2026-11-17

Scope: the SDK (`fangorn-network/fangorn`, branch `feat/readiness`, HEAD `1df8d71`) and the contracts (`fangorn-network/contracts`, branch `feat/mainnet-prep`, HEAD `0f178bb`).

Method: six parallel investigators with disjoint file ownership (contracts; SDK engine; crypto and paid flow; write path, feed and storage; CLI and staging; an adversarial cross-boundary reviewer), using Claude BugHunter methodology (`web3-audit`, `hunt-business-logic`,`hunt-race-condition`, `hunt-jwt-crypto`, `hunt-lfi`, `hunt-exceptional-conditions`, `hunt-nodejs`), followed by a coordinator integration pass that re-verified findings and reran every gate. Nothing was committed.

## A. Executive summary

- **Contracts:** no Critical or High code defects. The real risks are design and operations (section C). No changes were made to contract `src/`, because a merge to main triggers a live upgrade.
- **SDK:** one release blocker and about 30 other defects confirmed and fixed, each with a regression test.

**Release blocker: the SDK could not read the new contracts' logs.** Contracts commit `0f178bb` added `uint64 index, uint64 timestamp` to `Updated`, changing its topic (`0x4efe763c…1fe5` → `0xd3087e4c…e0bb`). Every SDK reader (`log`, `subscribe`, `repos`, stitch) silently saw nothing on the new contracts.

- Fixed: the SDK decodes both event versions, because the proxy is upgraded in place and existing history keeps the old topic.
- The first version of that fix introduced its own bug, caught only by the integration pass: viem 2.47.1 deduplicates `watchContractEvent` watchers by a key that **excludes the ABI** (address, args, batch, client uid, eventName, pollingInterval, strict, fromBlock). The two per-version watchers shared one poller: live events never arrived, or arrived twice. Rewritten as one watcher over both versions, with an e2e test that fails on the old code.
- Verified read-only against Base Sepolia: all 340 live log entries decode, and the client-rebuilt MMR root equals the on-chain `logRoot()`.

**Main residual risks:**

1. Raising a generation does not revoke past buyers.
2. CI auto-upgrades the contracts with a hot admin key.
3. Concurrent writes from one key collide on nonces.
4. In westmarch (out of scope), the buyer signs a USDC payment to an address the app chooses.

## B. Audit coverage

- **Contracts:** both contracts, deploy/upgrade scripts, and the CI upgrade workflow. Foundry fuzz and invariant suites added; 100% line, statement, branch and function coverage.
- **SDK:** engine (MST, CAR, commit head, MMR), crypto and paid flow, settlement client, write path, log reading and subscriptions, storage providers, config, ERC-8004, CLI and staging, and the in-memory test registry.
- **Cross-boundary:** SDK vs contract parity on a real anvil chain (commit head, EIP-712, repo id, MMR, ABI), interleaved writers and subscribers, and the paid flow end to end.
- **Tools run:** vitest, `tsc`, eslint, prettier, `forge test`, `forge coverage`, the e2e suite on anvil, read-only Base Sepolia checks, and 15 hand-applied mutants.
- **Not investigated:**
  - The real key server: it is not in either repo.
  - Real Semaphore proofs and real USDC ERC-3009 signatures: the e2e tests use mocks.
  - Deployed bytecode vs `deployed/`.
  - Node 20.

### Confirmed, unfixed (need a decision)

- **Generation raise does not revoke access (Medium, design).** `canRead` and `settled` ignore generation (`SettlementRegistry.sol:259-260, 289-294`), and the key server takes the generation from the caller. A whole-repo buyer at generation 0 receives later generations' keys. Found independently by two investigators; demonstrated by `test_generation_raise_does_not_revoke_access` and the adversarial e2e. If a raise is meant to revoke access, as WP2 §2 implies, this needs a contract change.
- **Old cheaper terms stay valid after a repricing (Medium, design).** Only `raiseGeneration` voids earlier signed terms (default deadline 365 days).
- **CI auto-upgrade (High for mainnet).** `.github/workflows/solidity.yml` puts the admin key in the job environment while ffi runs a floating `npx @openzeppelin/upgrades-core@^1.45.0`; actions are tag-pinned, not SHA-pinned; environment reviewers are optional. Use a multisig or timelock admin for mainnet, with CI proposing rather than signing.
- **SettlementRegistry `setAdmin` (Medium).** Single-step, no zero check (`:298-302`). DataRegistry's two-step pattern can be ported without breaking storage layout.
- **Concurrent writes from one key collide on nonces (Medium).** `replacement transaction underpriced`, reproduced on anvil with automine off (`src/e2e/adversarial.e2e.test.ts`, the two "DIFFERENT repos while a block is pending" tests). It fails loudly. viem's `nonceManager` was not adopted: if a send fails after a nonce is consumed it can leave a gap that stalls every later transaction, so it needs testing on a real RPC first.
- **Registry named as referrer strands the cut (Low).** One-line fix: add `referrer != address(this)` (`SettlementRegistry.sol:218-221`). Test: `test_registry_as_referrer_strands_the_cut`.
- **`membersOf` stops being readable at about 21k members (Low–Medium).** Measured 2,356 gas per member, about 21,222 members at a 50M `eth_call` cap; anyone can fill a free subject. Needs a paged getter or rebuilding from events. Test: `test_membersOf_gas_grows_per_member`.
- **`requestKey` accepts whatever key the key server returns (Low).** `src/crypto/paid.ts:298`. The fix needs a protocol change (a key commitment in the deposit). Pinned with `it.fails` in `src/crypto/crypto.fuzz.test.ts`.
- **A retried push after an ambiguous timeout reports "stale parent" (Medium).** The CLI is safe (`push` now says "Everything up to date"); direct SDK callers are not. Pinned with `it.fails` in `src/fangorn.fuzz.test.ts`. Suggested fix: make `settleable`/`pushCommit` idempotent.
- **`commitHead` hashes inputs with no valid DAG-CBOR form (Info).** Empty or non-CID `car`, and repo names that aren't valid UTF-8, move the head but can't be decoded off-chain.
- **Followers trust the publisher's event diff (design).** Nothing checks a commit's diff against the change between parent root and new root; only the publisher can exploit it, on their own repo.
- **No ignore file for `fangorn add` (design).** Only dot paths are skipped; `node_modules`, `id_rsa`, `credentials.json` are staged. `import "dotenv/config"` also loads a `.env` from the working directory, which can redirect the RPC and contracts.
- **Doc drift:** `docs/GUIDE.md:92` documents a `fangorn push --force` that doesn't exist; the contracts README references a `script/RotateAdmin.s.sol` and a `docs/spec.md` that don't exist.

### Out of scope, from code reading only (route to their owners)

- **westmarch `src/agent/x402.js:55` (High, plausible):** the buyer signs `receiveWithAuthorization` to the app's `payTo` and `asset` without comparing them to the settlement registry or USDC address, or the amount to `terms.price`. A malicious quote can take up to `maxPrice`.
- **webworker `barliman/src/x402.ts` (Low–Medium, plausible):** `AlreadyRegistered` is reported as a successful payment.
- **westmarch identity (design):** the Semaphore identity is derived from signing the fixed message `fangorn:identity:v1`. Any site that gets the user to sign it can read everything the user bought; wallets that don't sign deterministically pay but can't settle.

### Dismissed (with evidence)

- Self-referral cashback: documented in `docs/WHITEPAPER_2.md:236` as intended.
- `settle` checking only the record's own disable flag: matches the NatSpec; `canRead` still blocks.
- Proxy initialization front-running: atomic in `Upgrades.deployUUPSProxy`; implementations call `_disableInitializers()`.
- `updateBySig` replay: blocked by the parent check, confirmed by invariant tests.
- Nullifier cross-subject interference: impossible without a Poseidon collision.
- Front-running `register`/`settle`: the ERC-3009 nonce binds subject, commitment, referrer and salt; the settle message binds the reader.
- Prototype pollution in staging: fuzzed, none found.
- EIP-712 domain, typehash and SettlementRegistry ABI: exact match.
- AES-GCM nonce handling and AAD binding: verified by property tests.

## D. Code changes

- **SDK:** 22 files modified (about 770 insertions, 160 deletions), 19 new test files, and `fast-check` added as a dev dependency.
- **Contracts:** `foundry.toml` gains an `[invariant]` section; new `test/DataRegistry.invariant.t.sol`, `test/SettlementRegistry.invariant.t.sol`, `test/ffi/commitHead.mjs`. No `src/` changes.

Every fix has a regression test that fails without it; this was checked explicitly by reverting the watcher fix, the deposit fix, and the tamper checks (mutants M7, M12).

Behaviour changes worth reviewing:

- The CLI subscribe cursor is now at-least-once: a restart re-emits the last block's changes rather than risk losing them (`ponytail:` comment in `src/cli/cli.ts`).
- `ChainRegistry.watch` has no on-chain topic filter until no deployment still emits the old event (`ponytail:` comment in `src/contracts/data-registry/index.ts`).
- `sealRecords` now always returns the deposit first; `src/e2e/paid.e2e.test.ts` was updated accordingly.
- `subscribeAll` takes an optional `onSkip(err, entry)`; unreadable entries are reported and skipped instead of ending the stream.

- **SDK coverage** was about 57% lines at baseline. Weakest: `cli.ts` (0% before this audit), `pinata.ts` (1%), `ChainRegistry` (27%; its real behaviour is only tested in e2e).
- **e2e runs only on push to main, against an unpinned contracts branch.** That is how the ABI drift went unnoticed. Recommendation: run e2e on pull requests and pin the contracts `ref`.
- **The in-memory test registry still differs from the chain** in 7 documented ways: one entry per tick vs many per block, no mempool/gas/replacement, plain-error reverts, `CID.decode(car)` stricter than the contract, EOA-only signatures, synchronous watch, always-fresh reads.
- **Mutation testing** (15 mutants): 9 killed at baseline; M7 and M12 (tamper checks) survived and are now killed by `src/audit/untrusted-storage.test.ts`; M15 (MMR peak order) is caught only by e2e; M10, M13, M14 are near-equivalent.

## Audit process note

The first version of the new CLI test harness set HOME with `process.env = {...}`, which does not change `os.homedir()`, so its `init` tests overwrote the auditor's machine's real `~/.fangorn/config.json` with an anvil test key. The harness now refuses to run unless `homedir()` resolves to a tmpdir (`src/cli/cli.state.test.ts`, `isolated()`). Any test that touches HOME should use the same guard.
